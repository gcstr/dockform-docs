## Dockform v0.8 — Multi-Context, Auto-Discovery, and a Simpler Manifest

Dockform v0.8 is the biggest update since the project started. Large parts of the codebase have been rewritten to support multi-node deployments and convention-over-configuration. **This is a breaking release** — existing manifests will need to be updated. A [migration guide](https://dockform.io/introduction/migration_v08/) is available to walk you through the changes.

### Multi-context support

You can now deploy to multiple Docker daemons from a single manifest. Define your contexts — local, staging, production, or any number of remote servers — and Dockform handles them all:

```yaml
identifier: myapp

contexts:
  local: {}
  staging: {}
  production: {}
```

```bash
# Deploy everything
dockform apply

# Deploy to a single context
dockform apply --context production
```

No more jumping between directories to manage related stacks on different hosts.

### Automatic discovery

Dockform now discovers stacks, filesets, environment files, and secrets from your directory structure. A minimal manifest is all you need:

```yaml
identifier: myapp

contexts:
  default: {}
```

```
my-project/
├── dockform.yml
├── default/
│   ├── web/
│   │   ├── compose.yaml
│   │   ├── environment.env
│   │   └── secrets.env
│   └── db/
│       └── compose.yaml
```

Dockform finds `default/web` and `default/db` as stacks, loads their environment and secrets, and discovers filesets from `volumes/` directories — all without declaring them in the manifest. You can still augment discovered stacks with explicit config when needed (profiles, extra env vars, fileset overrides, etc.).

### Target individual stacks

Plan, apply, or destroy specific stacks without affecting the rest of your deployment:

```bash
dockform apply --stack default/web
dockform apply --stack default/web --stack default/api
dockform destroy --stack staging/old-service
```

Each targeted operation handles the stack's associated volumes, networks, and filesets.

### Simplified manifest schema

The `docker:` block, root-level `volumes:`, `networks:`, and `filesets:` are gone. Resources are now scoped to their context, and the manifest is shorter:

```yaml
# Before (v0.7)                    # After (v0.8)
docker:                             identifier: myapp
  context: default
  identifier: myapp                 contexts:
                                      default:
volumes:                                volumes:
  app-data: {}                            app-data: {}

stacks:                             # Stacks are discovered automatically
  web:
    root: ./web
```

### Other improvements

- **Fileset configuration in stacks** — ownership, permissions, excludes, apply mode, and restart targets can now be set directly in the `stacks:` block alongside discovery
- **Volume snapshots and restore** — portable `.tar.zst` snapshots with `dockform volume snapshot` and `dockform volume restore`
- **Terminal dashboard** — live fullscreen TUI showing stacks, container status, and logs with `dockform dashboard`
- **Deployment groups** — name groups of contexts/stacks for one-command deploys
- **Better error handling** — structured errors with operation context and classified exit codes

### Breaking changes

This release changes the manifest schema. See the [migration guide](https://dockform.io/introduction/migration_v08/) for a step-by-step walkthrough with before/after examples.
